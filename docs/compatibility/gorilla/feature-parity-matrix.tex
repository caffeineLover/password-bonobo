\section{Password Bonobo Feature-Parity Matrix}\label{password-bonobo-feature-parity-matrix}

\subsection{Contract boundaries}\label{contract-boundaries}

\begin{itemize}
\tightlist
\item
  PasswordSafe format authority governs file syntax, standard fields, identifiers, and lossless preservation.
\item
  A Gorilla-compatible requirement is claimed only from \passthrough{\lstinline!Confirmed!} or
  \passthrough{\lstinline!Supported!} dossier evidence.
\item
  A Bonobo product decision comes only from an approved Bonobo specification, not from Gorilla evidence.
\item
  An Unresolved evidence gap remains a research item and never establishes parity by inference.
\item
  No Bonobo metadata extension is approved for storage in a PasswordSafe file by this contract.
\item
  Deferred native capability boundary: native features are scheduled to their named owner and are not current parity.
\end{itemize}

The complete disposition vocabulary is \passthrough{\lstinline!Required!}, \nolinkurl{Modernized},
\passthrough{\lstinline!Deferred!}, \passthrough{\lstinline!Excluded!}, \passthrough{\lstinline!Bonobo extension!}, and
\nolinkurl{Unverified}. The \passthrough{\lstinline!Bonobo extension!} rows identify origin, not implementation status.
Their native delivery is deferred to the owner shown below. Biometric unlock has separate Android/ChromeOS and iOS
delivery rows so each row has one owner. Gorilla and Password Safe are asked only to preserve ordinary PasswordSafe
data; this matrix does not assert that either client understands Bonobo-native behavior or Bonobo metadata.

An \passthrough{\lstinline!Excluded!} row records an intentional Bonobo divergence and is not a Gorilla compatibility
requirement. It remains in the matrix so that the rejected upstream behavior and the governing Bonobo product rule are
both testable.

\subsection{Keys}\label{keys}

Owners are the eight exact subproject names from the approved program design:

\begin{itemize}
\tightlist
\item
  O1: Repository foundation and compatibility dossier.
\item
  O2: Lossless PasswordSafe core.
\item
  O3: Vault application core and desktop foundation.
\item
  O4: URL audit and cleanup.
\item
  O5: Provider-safe files and conflict resolution.
\item
  O6: Android and ChromeOS.
\item
  O7: iOS.
\item
  O8: Parity closure and stable release.
\end{itemize}

Platform keys are normative:

\begin{itemize}
\tightlist
\item
  D: Desktop (Windows, macOS, Linux).
\item
  A: Android.
\item
  C: ChromeOS.
\item
  I: iOS.
\item
  B: BSD.
\item
  ALL: D/A/C/I/B.
\end{itemize}

Evidence keys use the accepted behavior IDs in \href{./behavior-dossier.md}{the neutral dossier}. A range includes both
endpoints. \passthrough{\lstinline!GAP!} keys resolve in the register below. Approved specification keys are
\passthrough{\lstinline!S4!} for URL-audit design sections 5--14, \passthrough{\lstinline!S5!} for program design
sections 6--7, \passthrough{\lstinline!S6!} for program design section 9.1, \passthrough{\lstinline!S7!} for program
design section 9.2, and \passthrough{\lstinline!S8!} for program design section 10. A \passthrough{\lstinline!+!} joins
approved keys when both independently govern the row. Test IDs resolve in \href{./test-oracles.md}{the black-box oracle
catalog}.

\nolinkurl{GOR-FEAT-043} deliberately excludes two atomic Gorilla outcomes: \nolinkurl{GOR-BEH-006} warning-open for a
stored-HMAC mismatch and \nolinkurl{GOR-BEH-066} in-memory V3.0 defaulting when Version is absent. The official V3
Version header is mandatory and has two data bytes. Bonobo program design section 10 instead requires unsupported or
malformed content to fail closed, retain the original encrypted bytes, and create no replacement. The row does not
include \nolinkurl{GOR-BEH-058} rejection.

\nolinkurl{GOR-FEAT-044} requires observable ordinary-edit persistence and no loss, not a shared Save gesture. Gorilla
uses its explicit Save and backup path. Bonobo commits an ordinary edit when its complete form is confirmed; provider
unavailability retains the encrypted local edit as \passthrough{\lstinline!Sync pending!}. Save/discard close prompts
belong only to staged URL-audit cleanup.

\nolinkurl{GOR-FEAT-021} preserves normal merge classification, field-by-field resolution, and unresolved-record
preservation without inheriting the destructive close outcome in \nolinkurl{GOR-BEH-063}. Bonobo\textquotesingle s
no-loss authority requires a confirmed resolution or deletion to become transactional durable work before close. If
provider publication cannot complete, the work remains explicitly staged or conflicted and silent discard is blocked.

\nolinkurl{GOR-FEAT-045} isolates \nolinkurl{GOR-BEH-063} as an Excluded Gorilla-only characterization. It is neither a
modernized Bonobo merge behavior nor a cross-implementation passing oracle.

\subsection{Closure rules}\label{closure-rules}

\nolinkurl{Unverified} rows are explicit gaps, not parity commitments. Their oracles collect missing black-box evidence;
they do not prescribe a Bonobo result until the dossier and matrix are reviewed. All other Gorilla rows preserve only
the neutral observable contract and allow a modern interaction design.

PasswordSafe rows require semantic and unknown-field preservation independent of Gorilla\textquotesingle s current
behavior. The Bonobo-extension rows persist no custom PasswordSafe metadata under this contract. Native state such as
provider revisions, wrapped unlock material, and extension caches stays outside the vault. A future metadata field
requires a new, field-specific Gorilla and Password Safe round trip before its matrix disposition can change.
