\section{Password Bonobo Black-Box Test Oracles}\label{password-bonobo-black-box-test-oracles}

\subsection{Authority and scope}\label{authority-and-scope}

These scenarios specify observable inputs and outcomes, not internal design:

\begin{itemize}
\tightlist
\item
  \nolinkurl{PasswordSafe} means the official format is authoritative for file structure, fields, and preservation.
\item
  \passthrough{\lstinline!Gorilla!} means the pinned dossier observation is the compatibility authority.
\item
  \passthrough{\lstinline!Bonobo!} means an approved Bonobo specification is the product authority.
\end{itemize}

An Authority line may join these exact tokens with \passthrough{\lstinline!+!} when independent parts of one oracle have
different authorities. The Evidence and Required clients lines delimit each authority\textquotesingle s scope; one
authority is never inferred from another.

A Gorilla oracle marked as an evidence-gap closure test records the pinned client\textquotesingle s result before any
parity claim is approved. A Bonobo-native feature is not a Gorilla feature. Its cross-client step proves only that
ordinary PasswordSafe data remains usable; it never claims that Gorilla or Password Safe understands native state.

A preservable unknown field is valid PasswordSafe content. It is tested separately from malformed or unsupported
mandatory content and never triggers fail-closed behavior merely because Bonobo does not interpret it.

\subsection{Synthetic-data rules}\label{synthetic-data-rules}

Every value below is fabricated, non-secret, and confined to a disposable test directory. Reserved
\passthrough{\lstinline!.invalid!} hosts prevent accidental contact with a real service. Network scenarios map those
hosts to a controlled local endpoint. No personal vault, real credential, provider account, device account, or upstream
vault file is permitted.

\nolinkurl{PB-SYN-BASE} is a synthetic PasswordSafe V3 vault named \nolinkurl{pb-syn-main.psafe3} with:

\begin{itemize}
\tightlist
\item
  database UUID \nolinkurl{11111111-1111-4111-8111-111111111111};
\item
  master input \nolinkurl{fabricated-master-input-one};
\item
  record UUID \nolinkurl{22222222-2222-4222-8222-222222222222} in group \nolinkurl{Research.Sample};
\item
  title \passthrough{\lstinline!Alpha Portal!}, username \nolinkurl{sample-user}, and password
  \nolinkurl{fabricated-credential-value};
\item
  URL \nolinkurl{https://alpha.example.invalid/login} and note \passthrough{\lstinline!fabricated note A!};
\item
  unknown record field type \passthrough{\lstinline!0xE0!} with bytes
  \passthrough{\lstinline!66 61 62 72 69 63 61 74 65 64!};
